## 1. 项目概述

### 1.1 项目背景

- 抖音小游戏生态以"即点即玩、超短时长、强对抗反馈"为核心特征，用户从短视频、直播间、评论区等入口随机进入，单次停留预期极短。传统长线养成或重操作玩法在该生态下留存与转化表现不佳。
- 当前色彩辨识 / 反应力品类（如"眼力挑战""色块点击"类）在抖音已验证存在稳定流量：玩法理解成本接近 0、失败挫败感低、可反复重开，非常适合短视频演示与裂变。
- 纯单人刷分玩法缺乏对抗情绪，难以驱动复玩与分享。将"色彩匹配反应力"与"1v1 拔河胜负"结合，可同时具备**低门槛**与**强胜负情绪**两个关键要素，是本土化组合创新点。

### 1.2 产品定位

- **一句话定位**：一款"比谁眼更快、手更准"的解压 1v1 实时拔河色块对战小游戏。
- **玩法内核**：色彩识别 + 反应速度 + 短局对抗。
- **体验关键词**：3 秒看懂、30 秒一局、赢了想再来、输了不服气。
- **产品属性**：轻量竞技、非养成、无重数值、可无限重开。
- **商业化定位**：以激励视频广告为主要变现手段（复活 / 加速 / 奖励翻倍），轻度内购（可选主题皮肤）为次要手段。

### 1.3 目标用户

| 用户分层 | 画像描述 | 核心诉求 |
| --- | --- | --- |
| 主力人群 | 18–35 岁，抖音重度用户，碎片化时间游玩 | 快速爽感、胜负对抗、与好友互怼 |
| 次主力人群 | 36–50 岁，对色彩/眼力类玩法接受度高 | 操作简单、无需学习、随时可停 |
| 泛流量人群 | 短视频/直播引流而来的新用户 | 首屏 3 秒可玩、失败可立即重开 |
| 社交传播人群 | 愿意在评论区/群聊晒战绩的用户 | 战绩可分享、可挑战好友 |

- **使用场景**：等待间隙、通勤、睡前、直播间互动、短视频跳转后即玩。
- **设备环境**：以中低端安卓机型为主（占比预估 60%+），需保证低端机流畅运行（详见 5.4）。

### 1.4 核心卖点

1. **秒懂玩法**：目标颜色序列给什么顺序、底部就按序点什么，零教学成本。
2. **实时拔河可视化**：能量实时转化为绳子位移，局势一目了然，情绪反馈强烈。
3. **短局高对抗**：20～40 秒一局，输赢快、爽点密，天然适配碎片化场景。
4. **强社交传播**：胜负截图、挑战好友、好友榜，适配抖音社交裂变路径。
5. **低门槛可重开**：失败看广告复活或秒开下一局，不制造挫败流失。

## 2. 核心玩法详细说明

### 2.1 界面分区介绍

游戏主对局界面固定分为上、中、下三个区域，竖屏布局，比例为 **4:4:2**（顶部拔河视图 : 中部目标区 : 底部选色面板）。

| 区域 | 名称 | 功能 | 关键元素 |
| --- | --- | --- | --- |
| 顶部 | 拔河比赛状态视图 | 展示实时对战局势 | 拔河绳、双方小人、拉扯进度条、能量对比条、判定线、双方头像/昵称 |
| 中部 | 目标颜色区 | 给出本轮需匹配的颜色序列 | 目标颜色序列条带（3 段等宽彩色）、当前段高亮、条状倒计时、连击提示 |
| 底部 | 候选颜色面板 | 提供点击输入 | 多个候选颜色方块（含干扰色）、点击热区 |

**布局约束（研发必读）**

- 顶区占屏高约 40%，保证拔河动画有足够表现空间；中区 40%，底部 20%（含安全区）。
- 所有可点击热区最小尺寸 **88×88 px**（逻辑像素），间距 ≥ 12 px，避免误触。
- 顶部与中部、中部与底部之间以细分隔线/渐变过渡，视觉上分区清晰但不断裂。
- 需适配 iPhone 刘海屏、全面屏底部安全区、以及 16:9～21:9 的宽高比区间。

### 2.2 对战流程

**单局流程（正常对局）**

1. **加载/入场**：双方小人入场，加载 1.2s 内完成，不可出现黑屏。
2. **开局倒计时**：3 → 2 → 1，绳子居中，进度条归零。
3. **对局循环（每轮）**：
   - 一轮 = 一条 **3 段颜色序列**。中部刷新序列 → 玩家与对手同时开始点击 → 每点对一段即结算一次能量 → 能量实时映射为绳子位移。
   - 序列内逐段推进、不停顿；**点错当前段或该段超时即结束本轮**，走完 3 段也结束本轮。
   - 一轮结束后刷新下一条序列，仅保留 ≤150ms 的轮间停顿，保持节奏连贯。
4. **胜负判定**：当绳子位移越过任一侧判定线（达到阈值）或对局倒计时归零时结算。
5. **结算与跳转**：展示结果页（胜利/失败/平局按规则），提供"再来一局 / 分享 / 返回首页"。

**每段判定时序（关键）**

- 目标序列刷新 → 第 1 段输入窗口开启（默认 1.6s，随难度递减至 1.1s）→ 点对则该段结算能量并推进到下一段、**窗口重置为满**；点错或该段超时则结束本轮。
- 一条序列**固定 3 段，段内颜色互不重复**，玩家须按**先后顺序**依次点中；对已完成段或未轮到段重复点击不产生收益。
- 判定口径是"是否点中了当前待点段的目标色"，而非"点击次数"。

**异步实时说明**：为降低网络与匹配成本，对手侧默认采用**服务端模拟 AI 对手（Ghost）**，仅在"真人 PK 房间"玩法中启用真人实时对战。玩家体感上仍是 1v1 实时拔河，不区分对手身份。

### 2.3 胜负规则

| 结束条件 | 判定结果 |
| --- | --- |
| 我方能量位移越过"我方判定线" | 我方胜利 |
| 对方能量位移越过"对方判定线" | 我方失败 |
| 单局倒计时归零时未越线 | 按位移量比较：偏向我方 → 胜利；偏向对方 → 失败；完全居中（±阈值内）→ 平局 |

- **判定线阈值**：绳子中心相对屏幕中线偏移达到 **±220 px（逻辑像素）** 即判定越线（约等于屏幕宽度的 55%～60%，保证视觉上"明显被拉过去"）。
- **平局规则**：仅当倒计时结束且位移落在 ±20 px 内判定为平局；平局不计胜负入排行榜，可提示"再来一局决胜"。
- **抢先判定**：位移越线即时结算，无需等待倒计时结束，保证爽快感。

### 2.4 能量机制

**核心公式**

```
绳子位移(px) = (我方累计能量 - 对方累计能量) × 位移系数
位移系数 = 220 / 获胜所需净能量差
```

- 设"净能量差"达到 **80** 时越线（首版基线，见 §6.4 平衡调优结论与附录 A）。则位移系数 = 220 / 80 = **2.75 px / 能量点**。
- 即：当双方能量差达到 80 点，绳子正好被我方（或对方）拉过判定线。真实对局中因双方同时涨能量，实际净差需更大，单局典型节奏的目标带见 §6.3、实测与调优见 §6.4。

**能量来源**

| 行为 | 能量变化 | 说明 |
| --- | --- | --- |
| 点对一段（匹配成功） | +12 | 基础命中能量；一条序列最多结算 3 段 |
| 连续匹配成功（连击） | 连击加成 +2 ~ +8 | 见 6.2 连击表 |
| 匹配错误一次 | -6 | 干扰色惩罚，最低扣至 0，不出现负能量 |
| 未在规定窗口内操作 | 0 | 空轮不计能量 |
| 连击中断（点错） | 连击数清零 | 连带失去连击加成 |

- **能量不跨轮衰减**：已获得的能量保留，避免玩家因单段失误产生过大挫败。
- **对手能量**：由 AI 对手按难度参数**逐段**产出（与玩家同频，见 6.4 难度曲线），真人房间则由真人实时上传命中结果。

## 3. UI / 视觉设计要求

### 3.1 顶部区域：拔河状态视图

| 维度 | 规范 |
| --- | --- |
| 占屏比例 | 高度约 40%（含状态栏安全区） |
| 背景 | 亮蓝马卡龙天空（浅色渐变）+ 磨砂玻璃面板；薄荷色赛道按左右半屏分阵营染色（我方暖粉 / 对方冷蓝） |
| 拔河绳 | 水平居中，两端渐细，绳结居中；绳子材质需有粗度与阴影，越线时有物理拉伸感 |
| 双方小人 | 火柴人/卡通小人，带拉绳动作（两帧以上姿态交替），受力后身体前倾/后仰 |
| 拉扯进度条 | 绳子中心的滑块位置 = 位移可视化；两端各有判定线刻度，越线时判定线高亮闪烁 |
| 能量对比条 | 顶部或侧边显示双方能量条（我方 vs 对方），实时刷新数值，颜色阵营对应 |
| 双方信息 | 头像、昵称、阵营色描边；我方固定显示在视觉左/下侧，对方在右/上侧 |
| 位移映射 | 绳子偏移量与净能量差线性映射（见 2.4 公式），禁止阻尼延迟 > 100ms |

**视觉节奏要求**

- 绳子位移动画必须**跟手且平滑**，禁止出现拖尾延迟导致的"手感滞后"。
- 每次能量变化时，对应侧小人需有受力反馈（前倾/抖动），强化"拉"的物理感。
- 我方即将越线时，我方判定线脉冲发光；对手即将越线时，全屏轻微红色边缘警示。

### 3.2 中部区域：目标颜色区

| 维度 | 规范 |
| --- | --- |
| 占屏比例 | 高度约 40% |
| 目标样式 | 横向一条彩色条带居中，按序列段数（3 段）**等宽分段**；整体圆角 22 px；条带宽度受「屏宽 84% / 中区高度 92% / 每段 ≤132 px」三重约束 |
| 目标色 | 各段取高饱和色且**段间互不重复**；与底部干扰色有明显区分度，避免相邻色难辨认（如深蓝/深紫） |
| 段状态 | 已点对段压白降饱和（"已走过"）；**当前待点段**白色粗描边 + 外发光（指明"现在该点哪段"）；未轮到段保持高饱和原色；段间以白色细线分隔 |
| 背景 | 磨砂玻璃面板（半透明白）叠在浅色天空上；**目标色段本身不参与马卡龙化**——仍取高饱和色，靠白色厚描边 + 灰蓝柔和投影与浅底拉开层次，确保"一眼可辨" |
| 倒计时 | 条状进度条位于条带下方（表达"每段一格时间"），颜色随**当前段**剩余时间由绿渐变到红 |
| 连击提示 | 条带上方显示"连击 x N"，命中时数字弹跳放大 |

**辨识度要求（美术切图必读）**

- 候选色与**各段**目标色的色差（ΔE）需 ≥ 阈值，且干扰色**排除全部目标段颜色**，确保每一段都能在底部找到"唯一且明确"的正确答案。
- 同屏出现的颜色数量受难度控制（见 6.4），低难度优先使用高对比色（红/蓝/黄/绿）。
- 禁止使用纯文字标色名，颜色即唯一标识。

### 3.3 底部区域：候选颜色面板

| 维度 | 规范 |
| --- | --- |
| 占屏比例 | 高度约 20%（含底部安全区，避开 Home 条） |
| 候选块数量 | 3×2 = 6 格（低难度 4 格，高难度 6~9 格，见 6.4） |
| 单块尺寸 | 最小 88×88 px，推荐 96×96 px，圆角 12–16 px |
| 排布 | 网格对齐，间距 ≥ 12 px，手指盲点区域（屏幕两侧）不放置唯一正确答案 |
| 干扰色 | 与目标色同色系但明度/饱和度不同的"近似色"作为主要干扰源；**不得与任何目标段同色**（保证每段唯一答案） |
| 交互态 | 默认 / 按下 / 命中正确 / 命中错误 四态，需有明显视觉区分 |

- 底部面板需固定不随顶部位移抖动，避免玩家视觉追踪目标色时被干扰。
- 多候选色时需保证任意两点之间的色差可被普通手机屏幕区分（避免低端机色偏导致"看着一样"）。

### 3.4 全局视觉规范

| 项目 | 规范 |
| --- | --- |
| 风格 | 扁平 + 轻拟物，卡通化小人，强对比、高饱和、无真实照片元素 |
| 主色 | 全局统一「马卡龙」浅色系：首页为亮蓝天空，对局/结算为同色相的更淡天空 + 磨砂玻璃面板；我方阵营暖色（草莓粉系），对方阵营冷色（蓝莓蓝系） |
| 玩法色块 | 目标色与候选色**不参与马卡龙化**，保持高饱和（取值见 `config.palette`），仅靠白色厚描边 + 柔和投影保证浅底上的辨识度——辨识度要求优先于配色统一 |
| 字体 | 系统默认字体，数字使用等宽粗体，保证结算页秒读 |
| 分辨率 | 设计稿以 750×1334 为基准，切图输出 @2x/@3x，支持自适应缩放 |
| 性能 | 静态元素尽量使用合图图集（TexturePacker），减少 draw call |
| 无障碍 | 颜色同时辅以形状/图标微差异（可选），降低色弱用户辨识障碍 |
| 合规 | 不得出现"赌博""抽奖概率""真钱"等诱导性视觉元素 |

## 4. 游戏流程

### 4.1 开局匹配

1. **启动页**：Logo + 加载进度，1.2s 内可进入主界面；失败可重试。
2. **主界面（首页）**：
   - 中央大按钮"开始对战"（主 CTA，占视觉焦点）。
   - 副入口："好友 PK / 挑战好友"、"排行榜"、"设置"。
   - 显示我方昵称与头像、当前段位/胜场。
3. **匹配阶段**：
   - 点击开始后进入匹配动画（转圈 + 对手头像逐个闪过），匹配时长上限 **3s**，超时直接进入 AI 对局，不阻塞玩家。
   - 匹配成功展示"对手信息卡"约 1s，随后进入对局。
4. **对局准备**：3 秒倒计时（3-2-1-开始），双方就位。

### 4.2 对局进行

- 见 2.2 对战流程。对局中玩家仅需关注中部目标色与底部对应色块。
- 全程无弹窗打断（除了首次进入的引导与必要的弱网提示）。
- 弱网处理：若为真人房间，采用本地预测 + 服务端校验，网络波动不阻塞玩家操作，仅在超时后降级为 AI 结算。

### 4.3 结算页

| 元素 | 说明 |
| --- | --- |
| 结果展示 | 大号"胜利 / 失败 / 平局"，配阵营色高亮与结果动画（撒花/破碎） |
| 数据面板 | 本局命中**段**数、最高连击、命中率（= 命中段数 / 总判定段数）、对局时长、净能量差 |
| 主按钮 | "再来一局"（最高优先级，一键重开） |
| 分享按钮 | "晒战绩 / 挑战好友"（见 5.2） |
| 复活机制 | 仅"挑战模式"或特定模式提供"看广告复活再战"，详见 5.1 |
| 广告位 | 结算页底部原生/Banner 位（可选，非必要不出现） |
| 返回入口 | "返回首页"次级按钮 |

**结算情绪设计**：失败页需给"差一点"的措辞（如"就差 1 次命中！"），配合"再来一局"主按钮，最大化重开率。

## 5. 抖音小游戏适配设计

### 5.1 激励广告设计

激励视频是本游戏主要变现手段，须遵循"高频、低打扰、有明确收益"原则。

| 广告场景 | 触发时机 | 奖励内容 | 频次上限 |
| --- | --- | --- | --- |

- 复活广告仅在失败结算页出现，且 "再来一局" 与 "看广告复活" 二者只呈现明确的单一主 CTA，避免误触。

### 5.2 分享玩法

| 玩法 | 载体 | 说明 |

- 接入抖音小游戏**实名认证与防沉迷系统**：未实名/未成年按平台规则限制游玩时段与时长。

- 连续游戏时长达到平台阈值时弹出休息提示，强制中断（由平台能力接管为主）。
- 提供"家长/休息"提示入口，措辞温和，不制造恐慌。
- 无任何充值抽奖、无概率性付费内容，规避未成年人保护风险。

| 维度 | 目标值 | 措施 |

## 6. 数值规划

### 6.1 基础能量与位移

| 参数 | 基线值 | 说明 |
| --- | --- | --- |
| 越线所需净能量差 | 80 | 净能量差达此值即越线（首版基线，见附录 A） |
| 位移系数 | 2.75 px / 能量点 | 出自 2.4 公式（220 / 80） |
| 绳子位移上限 | ±220 px | 越线判定阈值 |
| 平局判定带宽 | ±20 px | 倒计时结束时落在其内判平局 |

### 6.2 匹配成功 / 失败数值

| 行为 | 数值 |
| --- | --- |
| 点对一段（匹配成功） | +12 能量；一条序列最多结算 3 段 |
| 点错一段（选错） | -6 能量（不低于 0），并结束本序列 |
| 当前段超时未点（空轮） | 0，并结束本序列 |
| 连击 3 次 | 第 3 次额外 +2 |
| 连击 5 次 | 第 5 次额外 +4 |
| 连击 8 次及以上 | 每次额外 +6 |
| 连击最高加成 | 单段命中最高 +18（12 基础 + 6 加成） |
| 连击中断 | 连击计数清零，已获能量保留 |

> 设计意图：鼓励稳定连击，惩罚无脑乱点；错误扣分控制在"中等痛感"（一次错误 ≈ 抵消半次成功），避免过度挫败。

### 6.3 对局时长

| 参数 | 数值 |
| --- | --- |
| 单局硬性时长上限 | 45 秒（超时按位移判定） |
| 典型对局时长 | 20～40 秒 |
| 每段输入窗口 | 1.6s（低难度）→ 1.1s（高难度）；点对后重置为满 |
| 轮次间隔（刷新停顿） | ≤ 150ms |
| 开局倒计时 | 3s |
| 结算动画时长 | ≤ 2s |

### 6.4 难度曲线

- 难度由四个维度共同控制：**候选色数量、色差接近度、输入窗口时长、对手强度**。
- 难度随对局内轮次递增（前 5 轮为热身），同时随玩家段位/胜率动态调整（ELO 式匹配）。

| 难度档 | 候选色数量 | 色差接近度 | 输入窗口 | 对手命中率 | 对手失误率 | 适用阶段 |
| --- | --- | --- | --- | --- | --- | --- |
| 简单 | 4 | 高（大色差） | 1.6s | 60% | 15% | 新手前 3 局 / 连败保护 |
| 普通 | 6 | 中 | 1.4s | 70% | 10% | 默认匹配 |
| 困难 | 6–9 | 低（近似色干扰） | 1.2s | 82% | 6% | 高段位 / 连胜后 |
| 地狱 | 9 | 极低（同色系多干扰） | 1.1s | 90% | 4% | 顶级段位 / 挑战模式 |

**对手能量产出模型（AI Ghost）**

```
对手单段能量 = 命中概率 × 基础能量(12) + 连击修正 - 失误概率 × 惩罚
```

- 系统按对手命中率**逐段**产出能量（与玩家同频），并加入 ±10% 随机浮动，制造"势均力敌"的紧张感。
- **平衡兜底**：当玩家净能量差落后 > 60 时，对手命中率临时下调 8%（连败保护，避免快速崩盘）；当玩家领先 > 60 时，对手命中率临时上调 5%（防碾压，保持对抗感）。此调整对玩家不可见。

**对局时长目标验证**：按普通档双方命中率约 65%~75% 计算，单方净能量增速约 12 × 0.7 ≈ 8.4 /段，双向对冲后净差增速约 3~5 点/段，达标越线（净差 80）需约 20~30 段（≈ 7~10 条序列）；以每段判定 0.4~0.6s、每 3 段一次 ≤150ms 轮间停顿估算，单局约 12~18s，**低于 §6.3 的 20~40s 目标带**（模拟未计入真实玩家的慢反应与结算动画，实测可能上浮）。首版维持越线净能量 80 与 3 段/轮，上线后按埋点实测统一调优。

> 数值调优建议：首版上线后，通过埋点采集"平均对局时长/平均命中率/胜负比"，若平均时长 > 40s 则下调越线阈值或提高基础能量，若 < 20s 则反向调整（提高越线阈值 / 增加每轮段数 / 拉长轮间停顿）。

## 7. 交互设计

### 7.1 点击反馈

| 事件 | 反馈 |
| --- | --- |
| 按下色块 | 色块缩放至 0.92、加深阴影、轻微震动（可选） |
| 命中正确 | 色块爆闪 + 绿色描边 + 粒子迸发 + 目标区吸收动画 |
| 命中错误 | 色块抖动 + 红色描边 + 短暂灰化 + 轻微震动 |
| 连击触发 | 连击数字弹跳放大，屏幕边缘轻微脉冲 |
| 越线瞬间 | 全屏闪白/闪光 + 绳子越线音效 + 紧张 BGM 收束 |

- 触控响应延迟 ≤ 50ms（本地判定），保证"手指跟得上眼睛"。
- 所有点击必须有**即时**视觉/触觉反馈，避免"点了没反应"的错觉。

### 7.2 动画效果

| 动画 | 时长 | 缓动 | 说明 |
| --- | --- | --- | --- |
| 开局倒计时 | 3s | 缩放弹入 | 数字大号，逐秒放大 |
| 目标序列刷新 | 200–300ms | 淡入 + 上浮 | 新目标条带入场 |
| 能量位移 | 100–200ms | 缓出（ease-out） | 绳子跟手位移，禁止延迟 |
| 小人拉绳 | 循环 | 逐帧/骨骼 | 交替姿态，体现拉扯 |
| 越线 | 400ms | 弹性 | 绳子越线定格 + 判定线闪烁 |
| 结算 | ≤2s | 序列 | 结果大字 + 数据面板逐项弹出 |

- 动画以"强化反馈"为目的，禁止为炫技牺牲帧率与响应速度。
- 低端机可降级：关闭粒子、减少特效层数，保留核心位移与点击反馈。

### 7.3 音效

| 场景 | 音效 |
| --- | --- |
| 命中正确 | 清脆"叮"音（音高随连击递增，构成音阶爽感） |
| 命中错误 | 低沉"嗡/咘"音 |
| 连击里程碑 | 上扬提示音（如连击 3/5/8 触发） |
| 能量位移 | 绳绷紧"吱"声，随张力变化 |
| 越线/胜负 | 胜利号角 / 失败下落音 |
| 背景音乐 | 节奏明快的短循环 BGM，紧张段落自动加速 |
| UI 点击 | 干净轻点音 |

- 音效遵循抖音小游戏音量规范，首屏不得自动播放过大音量，需提供静音开关。
- 连击音阶设计是本作"爽感"关键，需美术/音频重点打磨（音高随连击递增，形成"上台阶"的听觉奖励）。
- 所有音效需预加载，避免首次触发延迟。

## 9. 风险与注意事项

### 9.1 抖音小游戏审核要点

| 风险项 | 说明 | 规避措施 |
| --- | --- | --- |
| 玩法合规 | 不得含赌博、抽奖概率、真钱兑换 | 无概率付费、无抽奖；奖励为不可提现虚拟积分 |
| 广告合规 | 激励广告需用户主动触发，素材合规 | 不强制/不自动播放；接入官方广告 SDK 并遵循素材规范 |
| 未成年人保护 | 实名/防沉迷为硬性要求 | 强制接入平台实名与防沉迷能力，未成年不展示内购 |
| 版权素材 | 音效、字体、美术需自有或授权 | 使用可商用素材或原创，保留授权凭证 |
| 隐私合规 | 需隐私政策、权限最小化 | 仅申请必要权限，提供隐私政策入口 |
| 诱导分享 | 不得以奖励强制绑定分享 | 分享为增值行为，不与核心奖励强绑定 |
| 内容安全 | 昵称/头像需内容安全校验 | 接入内容安全接口，过滤违规昵称/头像 |
| 名称与类目 | 名称不得侵权、类目需正确 | 提前核对类目与名称，避免驳回 |

### 9.2 玩法与平衡性风险

| 风险 | 描述 | 应对 |
| --- | --- | --- |
| 色弱/色盲辨识 | 部分用户难以区分近似色 | 提供形状/图案辅助开关；难度档保留高对比色 |
| 低端机色偏 | 不同屏幕色彩还原差异导致"看着一样" | 控制色差下限，避免使用临界色差；真机多机型测试 |
| 手感滞后 | 位移延迟导致"点了没动" | 本地判定 + 位移动画 100–200ms 内响应，禁止服务端阻塞 |
| 数值失衡 | 对手过强/过弱导致一边倒 | AI 命中率浮动 + 落后/领先动态调节（见 6.4） |
| 单局过长 | 双方势均力敌导致对局超 40s | 越线阈值下调 + 硬性 45s 上限；埋点监控平均时长 |
| 无脑乱点 | 玩家乱点误打误撞 | 失误惩罚 + 连击清零，使乱点收益低于稳健操作 |
| 新鲜感衰减 | 玩法单一导致流失 | 规划变体模式与皮肤（8.2）快速迭代 |
| 广告体验 | 复活广告过于频繁 | 每局限 1 次，且与"再来一局"清晰区分 |
| 网络波动 | 真人 PK 卡顿影响体验 | 本地预测 + 服务端校验 + AI 兜底降级 |

### 9.3 上线前检查清单（DoD）

- [ ] 三分区界面在三类机型（低/中/高端）分辨率下无错位、无遮挡安全区。
- [ ] 对局流畅度：中端机稳定 60 FPS，低端机 ≥ 30 FPS。
- [ ] 匹配 3s 超时能正确进入 AI 对局，无卡死。
- [ ] 数值基线（越线阈值、连击加成）经内部对局验证，平均时长落在 20–40s。
- [ ] 激励广告成功/失败/超时三种路径均有兜底，不阻塞流程。
- [ ] 实名认证与防沉迷已接入并通过平台自测。
- [ ] 核心埋点齐全，可回收"平均时长/命中率/胜负比/广告观看率"。
- [ ] 分享功能在抖音端内可用，落地页直达对局。
- [ ] 素材版权与隐私合规材料齐备。
